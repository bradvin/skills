# Source and adaptation

## Public attribution and verification limits

This workflow adapts the five-first-user launch QA method posted by [@RoundtableSpace on X](https://x.com/RoundtableSpace/status/2111717667228770611). X oEmbed identified the display name as 0xMarioNawfal.

The source record distinguishes two levels of evidence:

- The complete five-persona prompt was recovered from the [FxTwitter mirror](https://api.fxtwitter.com/roundtablespace/status/2111717667228770611), not independently verified end to end against official X.
- [Official X oEmbed](https://publish.twitter.com/oembed?url=https%3A%2F%2Fx.com%2Froundtablespace%2Fstatus%2F2111717667228770611) corroborated the post ID, author handle, October 18, 2026 date, and opening excerpt, but truncated before the full five-persona prompt.

These are provenance claims from the source record, not a claim that a new retrieval was performed for this adaptation. Reply/thread completeness was not established; this procedure adapts the root-post method only. No full quoted post or raw retrieval artifacts are included.

## Method retained

The recovered method proposes five independent first-time-user lenses: impatient, skeptical, mobile on a 375px screen and slow 3G, literal-language comprehension, and bounded flow-breaking behavior. Each uses a real browser from landing page to first success, captures friction screenshots, and contributes to one consolidated fix queue. All five journeys are repeated after changes.

## Adaptation decisions

- Keep all five behavior lenses, actual browser journeys, 375px mobile testing, recorded slow-3G emulation, friction screenshots, consolidation and all-five retesting.
- Do not require the post's named model/version. Use an approved available browser-capable executor; the model claim is not independently validated.
- Rank by severity before distinct-persona frequency so a rare payment/data-loss defect is not buried under common cosmetic friction.
- Replace 'fix it all in one pass' with one scoped queue, authorized remediation and evidence-backed reruns. Keep release approval separate.
- Require isolated sessions/accounts, real evidence, explicit coverage gaps, and safety boundaries. Treat agent personas as simulation, never as five actual customers or measured conversion impact.
- Keep this as a procedural skill with handoff templates, not an installed browser runner. Installing or reading the skill does not execute a QA run or authorize production mutations.
